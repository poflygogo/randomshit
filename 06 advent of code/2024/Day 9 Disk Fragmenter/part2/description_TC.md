# --- 第二部分 ---

完成後，有兩件事立刻變得清晰。首先，磁碟確實有了更多連續的可用空間，就像端足類所希望的那樣。其次，電腦運行得慢多了！也許引入所有那些 [檔案系統碎片](https://en.wikipedia.org/wiki/File_system_fragmentation) 是一個壞主意？

熱切的端足類已經有了一個新計劃：不再移動個別區塊，他想嘗試透過移動**整個檔案**來壓縮磁碟上的檔案。

這次，試著將整個檔案移動到最左邊且能容納得下該檔案的可用空間區塊範圍。嘗試按照**檔案 ID 號碼遞減**的順序，從檔案 ID 號碼最大的檔案開始，將每個檔案移動恰好一次。如果在檔案的左側沒有足夠大的可用空間範圍來容納該檔案，則該檔案不移動。

上面的第一個例子現在進行的方式不同：

```text
00...111...2...333.44.5555.6666.777.888899
0099.111...2...333.44.5555.6666.777.8888..
0099.1117772...333.44.5555.6666.....8888..
0099.111777244.333....5555.6666.....8888..
00992111777.44.333....5555.6666.....8888..
```

更新檔案系統校驗和的過程是相同的；現在，這個例子的校驗和將是 `2858`。

重新開始，現在使用這種新方法來壓縮端足類的硬碟。**產生的檔案系統校驗和是多少？**
