# --- 第三天：仔細思考 (Mull It Over) ---

「我們的電腦出了點問題，所以我不知道我們是否有任何首席歷史學家的庫存！不過歡迎你去倉庫看看，」[北極雪橇租賃店](https://adventofcode.com/2020/day/2)那位稍微有點慌張的店主說道。歷史學家們便出發去查看。

店主轉向你。「你有辦法看看為什麼我們的電腦又出問題了嗎？」

電腦似乎正試圖執行一個程式，但它的記憶體（你的謎題輸入）已損壞。所有的指令都亂成一團！

看來這個程式的目標只是將一些數字相乘。它是透過像 `mul(X,Y)` 這樣的指令來完成的，其中 `X` 和 `Y` 都是 1 到 3 位數的數字。例如，`mul(44,46)` 將 `44` 乘以 `46` 得到結果 `2024`。同樣地，`mul(123,4)` 會將 `123` 乘以 `4`。

然而，因為程式的記憶體已損壞，所以還有許多無效的字元應該被忽略，即使它們看起來像是 `mul` 指令的一部分。像 `mul(4*`、`mul(6,9!`、`?(12,34)` 或 `mul ( 2 , 4 )` 這樣的序列都不起作用。

例如，考慮以下這段損壞的記憶體：

```text
xmul(2,4)%&mul[3,7]!@^do_not_mul(5,5)+mul(32,64]then(mul(11,8)mul(8,5))
```

只有四個標示的部分[^1]是真正的 `mul` 指令。將每個指令的結果相加會產生 `161` (`2*4 + 5*5 + 11*8 + 8*5`)。

掃描損壞的記憶體以尋找未損壞的 `mul` 指令。如果你將所有乘法運算的結果相加，你會得到什麼？

[^1]: MarkDown 語法有限，無法完整表示。此處指的四個標示的部分分別為 `mul(2,4)`、`mul(5,5)`、`mul(11,8)`、`mul(8,5)`。
